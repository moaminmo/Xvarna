# Governance

## Current model

XVARNA is currently founder-led. The project lead owns product scope, research
direction, release approval, and maintainer appointments. Material decisions
are recorded as RFCs or architecture decision records (ADRs).

## Roles

- **Contributor:** submits issues, documentation, tests, data, or code.
- **Reviewer:** reviews changes in an assigned area.
- **Maintainer:** can merge changes and is responsible for an area.
- **Release manager:** runs and records the release gates.
- **Project lead:** resolves scope and governance deadlocks.

## Decision process

Routine changes use pull-request review. Changes to public APIs, metric
semantics, file schemas, licensing, supported platforms, or release scope need
an RFC/ADR. Correctness and safety objections must be resolved with evidence;
schedule pressure alone is not sufficient to waive a P0 gate.

## Transparency

Public claims must link to a reproducible evidence artifact. Conflicts of
interest in benchmarks, reviews, and datasets should be disclosed.
