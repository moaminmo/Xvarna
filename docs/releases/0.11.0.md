# XVARNA 0.11.0 — VAYU Domain Acceleration

Released 2026-09-01 as a complete engineering milestone toward the 1.0 flagship.

## Product workflows

- `XV Target View`: CPU or cached VAYU Target/Weighted/Green View.
- `XV Corridor`: accelerated protected-aperture sampling and first-conflict attribution.
- `XV View Path`: path-major accelerated dynamic view time series and hotspots.
- All three preserve existing component GUIDs and output indices, accept `XV Scene` or `XV Backend`, and add complete backend provenance to their reports.
- All three CLI commands support backend/device/resource selection and fail-closed CPU parity.

## Engine and API

- Backend-neutral `RayQueryExecutor` shared by canonical f64 ZAMYAD and VAYU.
- Large ordered domain batches with bounded deterministic GPU dispatch splitting.
- Aggregate backend, adapter, batch/ray/dispatch, transfer, precision, and fallback reporting.
- Additive high-level C ABI and source-unit-aware .NET 8/.NET 10 session APIs.
- Rhino 8/.NET 8 and Rhino 9/.NET 10 packages share the same native Rust engine.

## Validation boundary

NVIDIA RTX 5060 and Intel Raptor Lake/Vulkan passed real-device Target View, Corridor, and Observer Path smoke cases with zero metric and identity/state mismatch against canonical CPU. See `docs/validation/vayu-domain-acceleration.md`. This release does not claim universal speedup; production-scale performance and failure-injection gates remain explicit.
