# XVARNA 0.12.0 — VAYU Production Throughput

Released 2026-09-01 as a complete engineering milestone toward the 1.0 flagship.

## Product workflows

- Repeated `XV Ray Query`, `XV Target View`, `XV Corridor`, and `XV View Path` requests reuse retained VAYU scratch resources after warm-up.
- New `XV Runtime` reports live request, ray, dispatch, memory, transfer, reuse, fallback, and device-health counters.
- `backend-benchmark` distinguishes cold allocation from configurable warm-up and measured min/p50/p95/mean throughput.

## Engine and API

- Lazy growth-bounded two-slot arena with persistent GPU buffers, parameter buffers, bind groups, and host staging.
- Paired command submission/readback with one device-poll window and deterministic ordered decode.
- Device-loss and uncaptured-error callbacks with retained health state, exact diagnostic, and explicit Auto/required-GPU behavior.
- Additive `xv_compute_get_runtime_stats` C ABI and .NET 8/.NET 10 `GetRuntimeStatistics()` API.
- Existing 64-byte batch and 464-byte DAENA execution layouts remain stable; new flags expose arena reuse.

## Validation boundary

Rust GPU tests execute cold and warm calls against a real available adapter and require one arena generation, reuse counters, and CPU parity. C layout and lifecycle tests, .NET 8/10 tests, Rhino 8/9 compile/runtime gates, and the multi-size throughput evidence runner cover the public surface. Driver-level fault injection and representative A/B/C model evidence remain explicit pre-1.0 gates; no universal speedup is claimed from the analytic smoke mesh.
